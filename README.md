# 読譜トレーニング

電子ピアノ（YAMAHA P-225 など）を MIDI で PC につなぎ、画面の音符を見て鍵盤を弾き、正誤と反応時間を測る個人用の読譜・初見練習アプリ。仕様は `SPEC.md`（v0.1）に準拠。

## 起動

```sh
npm install
npm run app      # ビルドして http://localhost:4173 で起動（ふだん使う・インストールするのはこちら）
npm run dev      # 開発用（http://localhost:5173、コードを書き換えるとすぐ反映。オフライン機能は無効）
npm test         # ユニットテスト（Vitest）
npm run build    # 型チェック + 本番ビルド（dist/）
```

## オフラインで使う（アプリとしてインストール）

PWA（インストールできる Web アプリ）として作ってある。アプリ本体と同梱の曲は、最初に開いたときにブラウザへ保存されるので、そのあとはネットにつながっていなくても、サーバーを止めていても動く。

1. `npm run app` を実行し、Chrome で http://localhost:4173 を開く（右上に「✓ オフラインでも使えます」と出れば準備完了）
2. アドレスバー右端のインストールのアイコン（またはメニュー →「キャスト、保存、共有」→「ページをアプリとしてインストール」）で「読譜トレーニング」をインストール
3. 以後はデスクトップ／アプリ一覧のアイコンから開く。ターミナルの `npm run app` は止めてよい

- 記録・追加した曲・設定は、このPCの Chrome の中（IndexedDB / localStorage）に保存される。ブラウザのサイトデータを消すと消えるので、統計画面の「記録を書き出す」でときどき保存しておく。
- コードを更新したら、もう一度 `npm run app` で開くと、次回起動時に新しい版へ自動で入れ替わる。
- 別のPCでも使いたい場合は、GitHub に push して GitHub Pages で公開すると（`.github/workflows/pages.yml`。Settings → Pages で Source を「GitHub Actions」にする）、HTTPS のアドレスからどのPCの Chrome でもインストールできる。Web MIDI は HTTPS か localhost でしか動かない。

## iPad で使う

iPad で開くには、まず GitHub Pages などで HTTPS のアドレスに公開する（上の項目）。iPad から PC の localhost には届かない。

- **画面の鍵盤で使う（Safari）**: 公開したアドレスを Safari で開き、共有ボタン →「ホーム画面に追加」。ホーム画面のアイコンから開くと、アドレスバーのない全画面のアプリとして動き、オフラインでも使える。Safari で開いたままなら、右上の「全画面」でも枠を消せる。
- **電子ピアノで弾く**: iPad の Safari（と、Safari と同じ仕組みで動く iPad 版の Chrome など）は Web MIDI に対応していないので、電子ピアノの音は受け取れない。Web MIDI に対応したブラウザアプリ（App Store の「Web MIDI Browser」「MIDIWeb Browser」など）で公開したアドレスを開く。P-225 は USB TO HOST（USB-B）と iPad の USB-C を USB-B ↔ USB-C ケーブル（または Apple の USB-C カメラアダプタ）でつなぐ。P-225 の Bluetooth は音の再生用で、MIDI には使えない。
  - これらのアプリでは、オフライン用の保存（Service Worker）や記録の保存先が Safari と別になることがある。記録はときどき「記録を書き出す」で保存しておく。
- タッチ操作向けの調整: ボタン・切り替えを指で押しやすい大きさにし、画面の鍵盤は大きめ（横になぞるとスクロール、和音は複数の指で同時に押せる）。キーボードのショートカット表示は出さない。統計のヒートマップはタップで詳細を出す。
- 曲を追加するときは「＋ 追加」から「ファイル」アプリの .musicxml / .mxl を選ぶ。.mxl は圧縮されたまま選んでよい（解凍しない）。iPad では拡張子で絞り込まず、読み込むときに中身で確かめ、楽譜でなければ理由を表示する（PDF は読めない）。
  - 追加した曲は、開いたブラウザ（アプリ）の中にだけ保存される。Safari と Web MIDI Browser では別々。IndexedDB が使えないアプリ内ブラウザでは localStorage に保存するので、数曲（合計数MB）までしか入らない。
- **すべての端末で使える曲にする（おすすめ）**: GitHub のリポジトリの `public/samples/` に .musicxml / .mxl をアップロードする（iPad のブラウザから GitHub の「Add file → Upload files」でできる）。公開時のビルドで曲一覧（`index.json`）が自動で作り直され、数分後にはどの端末・どのブラウザでも「同梱の曲」として選べる。

## 曲を増やす

方法は3つ。

1. **アプリから追加する（いちばん手軽）**: 曲モードの「曲を追加」で .musicxml / .mxl を選ぶ（複数まとめて選べる）。曲はブラウザ内のライブラリに保存され、オフラインでも選べる。不要になったら「選んだ曲をライブラリから削除」（練習記録は残る）。
2. **アプリに同梱する**: `public/samples/` にファイルを置くと、ビルド（`npm run build` / `npm run app`、GitHub Pages への公開時も）のたびに曲一覧（`public/samples/index.json`）が作り直される（手で作り直すなら `npm run songs:index`）。曲名は楽譜の題名から取る。`index.json` の title を手で書き換えれば、その名前が残る。次に `npm run app` するとオフライン用にも保存される。
3. **バッハのコラールをまとめて書き出す**: music21 同梱のコラール（約370曲、4声）を、ソプラノ+アルト／テノール+バスの2段譜にして書き出せる（いまは12曲同梱）。

   ```sh
   pip install music21
   python3 tools/make_samples.py public/samples --chorales 50
   npm run songs:index
   ```

### 楽譜（MusicXML）の手に入れ方

- **MuseScore**（無料の楽譜ソフト）: 自分で打ち込むか、開いた楽譜を「ファイル → エクスポート → MusicXML（.mxl / .musicxml）」で書き出す。musescore.com にはパブリックドメインの楽譜も多い（ダウンロードにはアカウントが必要）。
- **IMSLP の PDF → Audiveris で楽譜認識（OMR）**: 著作権の切れた曲のほとんどが PDF で手に入る。Audiveris で MusicXML に変換し、MuseScore で読み取りミスを直してから書き出す。
- **music21 のコーパス**: 上のコラールのほか、モーツァルトやベートーヴェンの一部の作品などが入っている（`corpus.parse(...)` → `write('musicxml')`）。

曲モードはピアノ譜（大譜表）の上の段を右手、下の段を左手として判定する。1段の曲（旋律だけ）は右手として扱う。装飾音・繰り返し記号・ペダル・アルペジオのずれは判定しない。

- 開くと Chrome が MIDI の使用許可を求めるので「許可」する。P-225 を USB TO HOST で接続すると右上にデバイス名が出る（抜き差しにも追従）。
- MIDI がなくても、画面下の仮想鍵盤（クリック）か PC キーボードで同じ操作ができる。
  - PC キーボード: `A`=ド、`W`=ド♯、`S`=レ … `K`=1オクターブ上のド。`Z` / `X` でオクターブを下げる / 上げる（初期値 A=C4）。キー位置で判定するので JIS 配列でも同じ。
- `Enter` で開始、`Esc` で途中終了。曲モード（待機）では `→` でいまの位置を飛ばす。
- 設定画面: 上のタイルで練習モードを選び、そのモードに要る設定だけをカードで表示する。タイミングの許容幅・メトロノーム・和音とみなす時間差・オクターブ違いの扱い・苦手な音を多めに出す、は「詳細設定」に畳んである。
- 画面下の鍵盤は「鍵盤を隠す / 表示」で切り替えられる。曲・流れ読みの画面では初期状態で隠して楽譜を大きく見せる（切り替えはそれぞれの画面ごとに覚える）。

## 現在できること（フェーズ1〜6）

- 練習モード
  - **反射モード（単音）**: 下記。
  - **形で読むモード（音程・和音）**: 2度〜7度・オクターブ、三和音（基本形・第1転回形・第2転回形）から選んだ形を出題（初期値: 3度・5度・オクターブ・三和音基本形）。音は調号どおりに積み、臨時記号ありなら1音だけ半音ずらす。和音は「最初の押鍵から一定時間内（初期値80ms、30〜150msで設定可）に押した音」をまとめて判定し、押せた音を緑、足りない音を橙、余計な音を赤で譜面に表示。仮想鍵盤はクリックで1音ずつなので、和音の音数ぶんクリックしたら判定する。
  - **曲モード（MusicXML）**: .musicxml / .mxl を開いて OpenSheetMusicDisplay で表示し、カーソルで進める。動作確認用に `public/samples/` に2曲入っている（メヌエット ト長調 BWV Anh. 114 の前半、コラール BWV 66.6 を2段にまとめたもの）。最後に開いたファイルはブラウザに保存され、次回も選べる。
    - **待機**: いまの位置の音（和音）がすべて押されるまでカーソルが止まる。右手と左手が多少ずれても、押せた音は覚えておく。押せた音は楽譜上で緑に、余計な音は下の小さな大譜表に赤で重ねて表示。
    - **テンポ**: ♩=指定のテンポ（空欄なら楽譜どおり）でカーソルが進み、止まらない。1小節ぶんカウントしてから始まる。押せた音を緑、間に合わなかった音を橙で表示し、ずれ（ms）を判定。許容幅（初期値 ±100 ms）に入った割合と、平均のずれ（走り気味／遅れ気味）を結果に出す。
    - **ランダム抜粋**: 設定の「範囲」で「ランダム抜粋」を選ぶと、曲からランダムに選んだ数小節（初期値 1〜3 小節、1〜8 で設定可）だけを楽譜に描き、そこだけ弾く。待機・テンポどちらでも使える（テンポは抜粋の最初の小節の頭から1小節カウント）。弾き終えると「✓ 弾けました」か、正解の数と間違えた小節を表示し、「もう一度」（`R`）か「次の抜粋」（`N`）を選ぶ。`Enter` は、ミスなしなら次の抜粋、間違えたらもう一度。直前と同じ範囲は続けて出さない。「苦手な小節を多めに」（初期値 ON）では、曲と判定する手が同じ記録から、小節ごとの直近40か所で間違えた割合を出し、重み = 1 + 12×間違えた割合（記録が少ないうちは 10% に寄せる）でその小節を選ぶ。まだ弾いていない小節も少し出やすく、ずっと弾けている小節は出にくくなる。選んだ小節が抜粋の頭・途中・終わりのどこかに入るように範囲をずらす。抜粋の頭が前の小節からのタイの後ろ側なら、そこから弾き始める音として判定する。`Esc` で終えると、弾いた抜粋ごとの結果（ミスなしで弾けた数、間違えたところ）を出す。記録は曲全体のときと同じく小節ごとに保存されるので、統計の「間違えやすい小節」にも入る。
    - **小節を指定**: 「範囲」で「小節を指定」を選び、楽譜に書かれた小節番号で「小節 5〜8」のように指定すると、その小節だけを楽譜に描いて繰り返し弾ける（待機・テンポどちらでも）。弾き終えるたびに結果を出し、「もう一度」（`R` / `Enter`）で同じ小節をもう一度弾く。何回目か・ミスなしで弾けた回数・何回続けてミスなしかを表示する。範囲の頭が前の小節からのタイの後ろ側なら、ランダム抜粋と同じく弾き始める音として判定する。曲にない小節番号を指定すると、その曲の小節番号の範囲を案内する。`Esc` で終えると、弾いた回ごとの結果を出す。
    - **判定する手**: 両手 / 右手のみ / 左手のみ（判定しない側は表示だけ）。ピアノ譜の上の段を右手、下の段を左手とみなす。
    - **判定しないもの**: 装飾音、繰り返し記号（展開せず書かれた順に1回だけ進む）、ペダル、アルペジオ記号付き和音のずれ。タイの後ろ側と、前の拍から伸ばしている音は押し直し不要。
    - **同じ音の持続**: 別の声部の長い音やタイがまだ鳴っている高さに、同じ音が書かれている場合（バッハの声部の共有音など）は、その鍵盤を押さえたまま（またはダンパーペダルで伸ばしたまま）なら弾けたとみなす。押し直してもよい。ふつうの連打（前の音が書かれた長さで終わってから同じ音）は押し直しが必要。
    - **反対の手が押さえている鍵盤**: 左手が伸ばしている音を右手がすぐ後に弾く場合など、同じ鍵盤は2回同時に押せないので打鍵が起きない。前の音として押した手と反対の手の音で、その鍵盤が押さえられたままなら、ほかの音がそろってから 0.25 秒たっても押さえたまま（または先の位置の音を弾き始めた）時点で弾けたとみなす。その間に持ち替えて弾き直せば、ふつうに正解。
    - **同じ手で押さえたままの鍵盤**: 小節の終わりの音を押さえたまま、次の和音の同じ鍵盤を弾き直さずに続けた場合も、和音のほかの音を弾いていれば、上と同じ条件（0.25 秒たっても押さえたまま、または先へ弾き進めた）で弾けたとみなす。和音ごと同じ音の連打（ほかに新しい音がない位置）は弾き直しが必要。テンポモードも同じ。確かめている 0.25 秒の間に鍵盤を離した場合は、さらに 0.5 秒だけ弾き直しを待ち、弾き直さなければ弾けたとみなす（この位置が来たときには押さえていたため）。
    - **戻る**: 待機モードでは `←` キー（または「戻る」ボタン）で1つ前の位置に戻って弾き直せる。戻った位置から先の色と結果は取り消し、弾き直した結果だけを記録する（待機モードの記録は、曲を終えたとき・画面を離れたときにまとめて保存する）。
    - **5小節戻る / 飛ばす**: 待機モードでは「5小節戻る」（`Shift`+`←`）で5小節前の小節の頭に戻り、そこから先の色と結果を取り消して弾き直せる。「5小節飛ばす」（`Shift`+`→`）で5小節先の小節の頭へ進む（曲や抜粋の終わりを越えるときは最後の小節の頭へ）。飛ばした間の位置は弾いていないものとして、記録せず結果にも数えない（1か所ずつの「飛ばす」は、弾けなかった位置として記録する）。
    - **止まったとき**: 待機モードで 2.5 秒ほど進めないと、足りない音を楽譜上で橙にして「足りない音: …」と表示する。`→` キー（または「飛ばす」ボタン）でその位置を飛ばせる（弾けなかった位置として記録）。
    - **待っている間に次の音を弾いたとき**: 押さえたままの鍵盤を確かめている 0.25 秒の間に次の音を弾いた場合（同じ鍵盤を弾き直した場合も）、いまの位置は済ませて、その押鍵を次の位置の音として判定する。
    - **先に押した音**: 和音を弾き終える前に先の位置の音（4か所先まで）を押してしまっても、その鍵盤を押さえていれば、その位置で弾けたとみなし、間違いには数えない。
    - **タイ**: タイの最初の音を弾くと、タイでつながった後ろ側の音符も同じ色になる。待機モードでは、カーソルが後ろ側の位置を過ぎたとき（その位置を弾き終えたとき）、テンポモードではカーソルがそこまで進んだとき。同じ鍵盤の音が複数の声部に重なっている場合も、すべての音符に色を付ける。
    - 連符の時刻の端数（MuseScore の3連符など）は、わずかな許容幅で同じ時刻として扱う。
  - **流れ読みモード（スクロール）**: ランダムなフレーズが右から左へ流れ、縦線に来た音を弾く。1小節（4拍）カウントしてから始まり、間違えても止まらない。押せた音を緑、間に合わなかった音を橙、違う音を押したらその高さに赤い符頭と音名を重ねる。各音の正誤とタイミングのずれ（ms）を記録。
    - 設定: 小節数、テンポ、リズム（4分音符のみ / 2分・4分・8分を混ぜる）、跳躍の上限（2度〜オクターブ、初期値6度）。譜表・音域・調号・臨時記号は反射モードと同じ設定を使う（大譜表なら小節ごとに上下どちらかの段）。
    - フレーズは調の音階上を歩き、順次進行を出やすくし、4度以上跳んだ後は反対向きの順次進行で戻りやすくしている（跳躍の連続を避ける）。最後の小節は全音符。小節内の臨時記号は同じ高さの後の音にも効く扱いで、戻すときはナチュラルを書く。
- 反射モードの詳細: 正しい鍵盤を押すと音符が緑になり次の問題へ。間違えると押した音を赤で譜面に重ねて表示（同じ段に、調号を考慮した綴りで。変イ長調で D♭ を押せば臨時記号なしの D、F♯ を押せば ♯ 付きで出る）。正解するまで次に進まない。
- 1問ごとの反応時間、終了時に正答率・平均反応時間・1問ずつの記録を表示。正誤と反応時間は**最初の押鍵**で決める。
- 設定（ブラウザに保存される）
  - 譜表: ト音記号 / ヘ音記号 / 大譜表（問題ごとに上下どちらかの段）
  - 音域: 段ごとに最低音〜最高音（加線4本まで。選択肢に加線の本数を表示）
  - 調号: なし / 指定（15種） / 問題ごとにランダム（♯・♭ を何個までにするか指定）
  - 臨時記号: 混ぜる / 混ぜない（混ぜると約3割の問題で ♯・♭・♮ が付く。E♯・B♯・F♭・C♭ は出さない）
  - 問題数 or 制限時間、オクターブ違いを正解とみなす
  - 苦手な音を多めに出す（初期値 ON）
- 記録の保存（IndexedDB）: 1問ごとに 日時・モード・段・調号・期待音・最初に押した音・正誤・反応時間・押した回数 を保存。正解した時点（または終了時）に保存するので、やり直し回数も残る。
- 統計画面: 流れ読みの記録（直近10回のテンポ・正答率・ずれ）、曲ごとの記録（正答率・間違えやすい小節・ずれの平均）、形ごとの正答率（形で読むモード）、段 × 音ごとの正答率ヒートマップ（反射モード）（行=オクターブ、列=音名。マスに正答率と正解時の平均反応時間）、ホバーで詳細（よく押し間違える音など）、苦手な音トップ10。正答率と反応時間は各音の**直近20回**で計算するので、上達がすぐ反映される。
- 苦手音の重点出題: 出題の重み = 1 + 6×誤答率 + 2×遅さ。誤答率は回答が少ないうちは 20% に寄せる（1回のミスで極端に偏らない。未出題の音も少し出やすい）。遅さは正解時の平均反応が全体平均の何倍か（1倍で0、2倍以上で1）。
- 記録の書き出し（JSON）・読み込み・全消去。記録はこのPCのこのブラウザの中だけにあるので、ときどき書き出しておくと安心。

## 構成

```
src/
  music/       音名⇔MIDI番号の変換、音部記号ごとの音域、調号（共通の音楽理論）
  midi/        Web MIDI 入力、メッセージ解析、和音グルーピング（フェーズ4で使用）
  input/       仮想鍵盤・PCキーボード（MIDIと同じ NoteEvent を出す）、入力の集約
  generator/   ランダム出題（単音・形・流れ読みのフレーズ）
  judge/       判定（純粋関数）。集合比較で 正しい音 / 足りない音 / 余計な音 を返す。
               曲モードの待機判定（WaitStepJudge）とテンポ判定（TimedMatcher）も
  render/      VexFlow による五線描画と色付け、流れ読みの横長の譜面（phraseRenderer）とスクロール位置の計算（timeline）
  stats/       回答記録と集計
  ui/          画面とモード進行
  score/       MusicXML の表示とカーソル（OSMD）、判定用のステップ列への変換（純粋関数）、曲のライブラリ
  storage/     IndexedDB の接続（回答記録と曲のライブラリで共通）
  audio/       メトロノーム（Web Audio）と拍の予約（BeatClock。曲のテンポモードと流れ読みで共通）
```

判定・出題・MIDI解析・集計は UI から分離しており、`*.test.ts` にユニットテストがある（単音一致、オクターブ違い ON/OFF、異名同音、和音の過不足、和音グルーピングなど）。

## メモ

- 反射モードでは単音なので押鍵ごとに即判定し、形で読むモードでは和音グルーピング（`ChordGrouper`、初期値 80ms）でまとめてから判定する。
- テンポのある判定（曲のテンポモード・流れ読み）は `TimedMatcher` で共通。押鍵を、同じ音で時刻が窓の中にあるいちばん近い目標に結び付ける。
- 判定はノート番号のみで行うため、異名同音は自然に同一扱い。
